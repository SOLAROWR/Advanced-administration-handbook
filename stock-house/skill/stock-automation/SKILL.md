# 주식자동화: 1인 투자 하우스

Anthropic의 financial-services-plugins "Equity Research" 워크플로우를 한국 개인투자자용으로 옮긴 스킬이다. 사용자는 **코딩·금융 초보자**이고 유튜브와 블로그를 운영한다. 그래서 결과물은 그대로 영상 대본이나 블로그 글의 재료가 될 만큼 **쉽고, 숫자에 출처가 붙어 있어야** 한다.

## 워크플로우 한눈에 보기

| Action | 단계 | 커맨드 | 하는 일 | 다음 단계로 넘기는 것 |
|---|---|---|---|---|
| 1 종목탐색 | ① | `/sector <주제>` | 막연한 호기심을 산업 지도로 정리 | `/screen`에 넣을 문장 |
| | ② | `/screen <조건>` | 후보 10개 내외를 채점해 3~5개로 압축 | 1순위 종목 |
| | ③ | `/earnings-analysis <종목>` | 8개 분기 실적, 동종사 비교, 40점 채점 | 핵심 지표 |
| | ④ | `/earnings-preview <종목>` | 다음 실적 체크포인트 5개 기준표 | 채점 기준 |
| | ⑤ | `/initiate-coverage <종목>` | 실적 추정, 목표주가, 분할매수 계획 | 목표가, 재검토 조건 |
| 2 추적관찰 | ⑥ | `/thesis <종목>` | 핵심 가정 4개와 훼손 조건 고정 | 점검 지표 |
| | ⑦ | `/catalysts <종목>` | 앞으로 3개월 이벤트 캘린더 | 할 일 목록 |
| | ⑧ | `/earnings <종목>` | 실적 발표 후 Beat/Miss와 Thesis 채점 | Thesis 갱신 |
| 3 루틴 | ⑨ | `/morning-note` | 매일 아침 5분 요약 | – |
| 부가 | – | "워드로 묶어줘" | 보고서를 하나의 .docx로 | – |

사용자가 커맨드 없이 말해도 의도에 맞는 단계를 고른다. 예: "반도체 관련주 정리해줘"는 ①, "한미반도체 사도 돼?"는 ③과 ⑤.

**각 단계의 상세 지시(구성, 채점 기준, 계산법)는 `references/stages.md`에 있다. 해당 단계 섹션을 반드시 읽고 시작한다.**

## 작업 공간 (파일 저장 규칙)

이전 단계의 결과를 다음 단계가 읽어야 워크플로우가 이어진다. 그래서 파일 위치를 일정하게 지킨다.

```
<작업폴더>/            ← 사용자가 정한 곳. 없으면 현재 폴더에 stock-house/ 생성
├── portfolio.md       ← 보유·관심 종목, 관심 섹터 (없으면 템플릿으로 생성)
├── theses/<종목명>.md ← 종목별 투자 논리
└── reports/YYYY-MM-DD_<단계>_<주제>.md
```

- 시작 전에 `portfolio.md`, 같은 종목·주제의 이전 보고서, `theses/` 파일을 먼저 읽는다. 이전 결론과 연결해야 하기 때문이다(예: preview의 체크포인트로 earnings를 채점).
- `portfolio.md`가 없으면 `references/stages.md` 맨 끝의 템플릿으로 만든다. 예시 줄은 "(예시)"로 표시해서 실제 보유로 착각하지 않게 한다.
- 저장소(git)에서 작업 중이면 저장 후 커밋하고 푸시한다.

## 공통 원칙

1. **숫자는 검색으로 확인하고, 숫자마다 출처와 기준일을 단다.** 기억으로 숫자를 지어내면 사용자가 그 숫자로 돈을 잃을 수 있다. 확인 못 한 값은 빈칸 대신 "확인 필요"로 쓴다.
2. **직접 계산한 값은 "직접 계산"이라고 밝히고 식을 보여준다.** 예: "4Q24 = 연간 − 1~3분기 합계". 분기 실적이 기사에 없을 때 연간 실적이나 전년 대비 증감률로 역산하는 것은 유용하다. 다만 출처가 있는 값과 구분해야 한다.
3. **추정이 섞인 점수와 수치에는 `*`를 붙인다.** 블로그, 단일 뉴스레터, AI 요약 사이트 출처는 "확인 필요" 꼬리표를 단다.
4. **쉬운 말로 쓴다.** 전문용어는 처음 나올 때 괄호로 풀이한다. 예: "PER(주가가 1년 이익의 몇 배인지)". 비유를 하나 넣으면 이해가 빨라진다. 예: "3~4년 예약이 꽉 찬 맛집 vs 대형 주문이 오면 대박인 케이터링 업체".
5. **모든 보고서 맨 끝에 다음 문구를 넣는다.**
   > ⚠️ 본 자료는 정보 정리용이며 투자 권유가 아닙니다. 최종 투자 판단과 책임은 본인에게 있습니다.
6. **매매 주문은 하지 않는다.** 분석, 기록, 알림까지만 한다.
7. **보고서 끝에는 항상 "다음 단계" 커맨드를 코드블록으로 제안한다.** 사용자가 그대로 복사해서 이어갈 수 있다.
8. **"확인하지 못한 것" 목록을 보고서 끝(출처 위)에 둔다.** 사용자가 무엇을 직접 확인해야 하는지 알 수 있다.

## 데이터 수집 요령 (실전에서 배운 것)

- **우선 출처.** 한국 주식은 DART 공시, KIND, 회사 IR, 증권사 리포트(stock.pstatic.net 등), 주요 경제지를 쓴다. 미국 주식은 SEC, 회사 IR, 실적 발표문을 쓴다.
- **검색은 한 번에 한 주제, 여러 개를 병렬로.** 예: "<종목> 2026년 2분기 실적 매출 영업이익", "<종목> 북미 매출 비중", "<종목> 목표주가 하향". 종목 여러 개를 한 쿼리에 섞으면 결과가 흐려진다.
- **날짜 함정.** 같은 "10월 8일" 기사라도 다른 연도일 수 있다. 지수 수준이나 맥락으로 연도를 반드시 확인한다. 예전 연도 기사를 최신 값으로 쓰지 않는다.
- **최신 주가는 검색에 잘 안 잡힌다.** 확인된 가장 최근 종가와 그 날짜를 쓰고, 사용자에게 현재가 확인을 요청한다. 목표가 판단이 현재가에 좌우되면 "현재가가 X원 이하일 때만 매수 구간"처럼 **조건부로** 쓴다.
- **컨센서스가 안 잡히면 직접 기준선을 만든다.** 최근 분기 평균, 이익률 추세, 수주 증가율로 만든다. 그리고 "증권사 연간 전망을 맞추려면 하반기에 분기당 얼마가 필요한가"를 역산한다. 기대가 과한지 보여주는 좋은 신호다.
- **Alpha Vantage 도구가 있으면** 시세(SPY·QQQ·DIA·EWY ETF, 개별 미국주), 환율, 미국 10년물 금리, WTI, 비트코인을 가져온다. 무료 키는 **초당 1회, 하루 25회** 제한이라 호출을 하나씩 순서대로 한다. 뉴스 엔드포인트는 유료라 실패할 수 있다. 일별 시계열은 응답이 커서 파일로 저장되므로 `jq -r '.sample_data'`로 앞부분만 읽는다.
- **한국 휴장일을 확인한다.** 주말, 설·추석 연휴, 3/1, 5/5, 6/6, 8/15, 10/3, 10/9, 12/25 등에는 "마지막 거래일"을 명시한다.
- **환율도 실적 변수다.** 수출 비중이 큰 종목은 원화 강세가 원화 환산 매출을 줄인다. 달러 기준 수주와 원화 기준 매출을 구분해서 해석한다.

## Word(.docx)로 묶기

사용자가 "워드로", "docx로", "한 파일로 묶어줘"라고 하면 다음 명령을 쓴다.

```bash
bash <스킬경로>/scripts/build_docx.sh <작업폴더> <출력파일.docx> [보고서 파일들...]
```

- 보고서 파일을 생략하면 워크플로우 순서(sector, screen, earnings-analysis, earnings-preview, initiate-coverage, thesis, catalysts, earnings, morning-note)로 자동 정렬한다.
- 스크립트는 표지와 목차 표를 만든다. 보고서마다 새 페이지에서 시작하고, 표 머리줄은 네이비(#1F3B57), 글꼴은 맑은 고딕을 쓴다. 표 칸 너비는 내용 길이에 맞게 자동 조절한다.
- pandoc이 필요하다. 만든 뒤 가능하면 PDF로 렌더링해 표가 깨지지 않았는지 눈으로 확인한다.

## 반복 실행 (모닝노트 예약)

사용자가 "매일 아침 X시에 모닝노트"라고 하면 사용 환경의 예약 기능으로 등록한다(Routine, cron 등). 시간대는 Asia/Seoul로 하고, 평일만 원하면 월~금으로 맞춘다. 예약 프롬프트에는 작업폴더 경로와 `references/stages.md`의 ⑨ 모닝노트 지시를 따르라는 내용, 저장·푸시 방법을 넣는다. 그래야 맥락 없이 실행돼도 같은 품질이 나온다.

## 참고 파일

- `references/stages.md`: 9단계 각각의 구성, 채점 기준, 계산법, portfolio 템플릿. **단계마다 해당 섹션을 읽는다.**
- `references/examples/`: 실제로 만든 보고서 예시(커버리지 개시, 실적 프리뷰, Thesis). 분량, 표 구성, 말투의 기준으로 참고한다. 다만 숫자는 2026-10-11 기준이라 재사용하지 않는다.
- `scripts/build_docx.sh`, `scripts/table_widths.lua`, `assets/reference.docx`: Word 묶음 도구.
